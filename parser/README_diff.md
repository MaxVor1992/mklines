# Парсер поисковой выдачи Яндекс и Google

**Веб-инструмент для анализа позиций сайтов в поисковой выдаче Яндекс и Google**

Проект расположен по адресу: [https://mklines.ru/parser/index](https://mklines.ru/parser/index)

---

## 📋 Описание

Инструмент предназначен для парсинга поисковой выдачи Яндекс и Google с целью анализа сайтов, находящихся на 1, 2, 3 страницах результатов поиска. Позволяет отслеживать позиции сайтов по ключевым словам, проводить кластеризацию запросов и экспортировать результаты.

## ⚙️ Логика работы

### Входные данные (форма на странице)

| Элемент | ID | Описание |
|---------|-----|----------|
| Ключевые слова | `keys` | Список запросов для проверки (максимум 50 фраз, каждая с новой строки) |
| Поисковая система | `engine` | Выбор системы: Яндекс XML (river), Яндекс XML (официальный), Google JS, Google XML |
| Регион | `region_y_chosen` / `region-g` | Географический регион для проверки выдачи |
| Количество итераций | `iteration` | Число повторений проверки (1-3) для усреднения позиций |
| Глубина проверки | `depth-*` | ТОП-10 (1 страница), ТОП-20 (2 страницы), ТОП-30 (3 страницы) |
| Кеширование | `docache_id` | Если активен, повторяющиеся запросы берутся из кэша |

### Процесс парсинга

1. **Ввод данных**: Пользователь вводит ключевые слова в поле `id="keys"`
2. **Выбор поисковика**: В `id="engine"` выбирается Яндекс или Google
3. **Выбор региона**: В `id="region_y_chosen"` указывается регион проверки
4. **Настройка итераций**: В `id="iteration"` задаётся количество проверок (для усреднения)
5. **Глубина парсинга**:
   - `id="depth-10"` — первая страница выдачи (ТОП-10)
   - `id="depth-20"` — первые две страницы (ТОП-20)
   - `id="depth-30"` — первые три страницы (ТОП-30)
6. **Кеширование**: При активном `id="docache_id"` повторные запросы не выполняются, а берутся из кэша
   - **Время жизни кэша**: 12 часов (настроено в `for_cache.py`)
7. **Запуск**: Клик по кнопке `class="parser-submit"` запускает парсинг

### Доступные движки парсинга

| Код | Движок | Описание |
|-----|--------|----------|
| 11 | Native Yandex | Нативный парсинг через requests |
| 12 | Yandex XML River | Через XML API (xmlriver) |
| 13 | Yandex XML Official | Официальный Яндекс XML |
| 21 | Google JS | Парсинг через Selenium |
| 22 | Google XML | Через XML API |

## 🔧 Функционал

### 1. Парсинг поисковой выдачи
- Поддержка Яндекс и Google
- Выбор региона парсинга
- Множественные итерации для усреднения результатов
- Глубина сканирования до 30 позиций

### 2. Кеширование запросов
- Автоматическое сохранение результатов
- Время хранения: **12 часов**
- Экономия лимитов пользователя при повторных запросах
- Реализовано через декоратор `@timed_lru_cache` в `for_cache.py`

### 3. Кластеризация запросов
- Активация через форму `id="cluster-form"`
- Поле `class="klastery_percent"` для указания процента пересечений URL
- **Логика**:
  - При 30% — таблицы объединяются в кластер, если 30% URL совпадают
  - При 50% — требуется 50% совпадений URL
- Алгоритм основан на расчёте пересечений множеств URL между запросами
- Реализовано в `resultobj.py` (метод `calc_clusters`)

### 4. Экспорт данных
- **CSV**: Кнопка `class="download-csv"` → скачивание `results.csv`
- **XLS**: Кнопка `class="download-xls"` → скачивание `results.xls`
- Формирование файлов происходит в `parser_utils.py`

### 5. Копирование URL
- Клик по `data-clip="#clipboard-block-1"` копирует все URL из таблицы `class="answer-table"` в буфер обмена
- Данные для копирования находятся в скрытом блоке `id="clipboard-block-{номер}"`

### 6. Система пользователей
- Регистрация и авторизация
- Роли: **User**, **Admin**
- Лимиты запросов для пользователей
- Админ-панель для управления пользователями

## 🚀 Установка и запуск

### Требования
- Python 3.8
- Apache + mod_wsgi (для production на Beget)
- SQLite (встроен в Python)

### Локальная разработка

```bash
# Перейти в директорию проекта
cd /workspace/parser

# Активировать виртуальное окружение
source venv38_flask/bin/activate  # Linux/Mac
# или
venv38_flask\Scripts\activate  # Windows

# Установить зависимости
pip install -r parser_app/requirements.txt

# Дополнительные пакеты (не в requirements.txt)
pip install flask flask-sqlalchemy flask-login flask-admin flask-security xlwt selenium scikit-learn pandas distance
```

### Production (Beget)

1. Разместить файлы на сервере Beget
2. Настроить `passenger_wsgi.py` с правильными путями:
   ```python
   sys.path.append('/home/r/rapcooc5/mklines/public_html/parser/parser_app')

   ```
3. Приложение автоматически инициализируется через:
   ```python
   application = parser_app.create_app()
   ```

## 🎯 Особенности реализации

### Кластеризация
Алгоритм кластеризации в `resultobj.py`:
1. Для каждого запроса формируется множество URL
2. Вычисляется процент пересечения между множествами
3. Запросы с пересечением ≥ барьера объединяются в кластер
4. Каждому кластеру присваивается уникальный цвет

### Кэширование
Декоратор `@timed_lru_cache` в `for_cache.py`:
- Время жизни: 12 часов (43200 секунд)
- Максимальный размер: 9512 записей
- Автоматическая очистка по истечении времени

### Многопоточность
Модуль `my_threads.py` реализует параллельный парсинг для ускорения обработки больших списков запросов.
